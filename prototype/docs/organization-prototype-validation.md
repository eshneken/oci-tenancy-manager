# Organization prototype validation

Historical prototype behavior record; current production-source qualification belongs to
[the test policy](../../docs/engineering-test-plan.md) and [current implementation reference](../../docs/reference/README.md).
Private original feeds, employee analysis and local-machine recovery details are not distributed.

## Reproduce with synthetic inputs

From prototype/, install its locked environment and run the commands in [the prototype guide](../README.md).
Use the invented fixture and disposable PostgreSQL test driver. No private workbook, stored connection
or persistent human workspace is required. Never point the test driver at a saved installation.

The historical prototype exercised typed feed/profile separation, identity/graph validation,
reference-only managers, current/proposed snapshots, complete-census absence, capture/source order,
stable identity merges, durable exception decisions and individual/shared associations. Database
regressions separately exercise sealed snapshots, scoped relationships, rollback and competing
publication. Local actor labels, synchronous simulated OCI success and local reset controls are
lab mechanisms; they are not production authentication or durable provider qualification.

## Interpretation limits

Prior raw receipts and source-analysis reports remain private historical evidence. They are not
required checkout artifacts, current suite counts or claims about an actual organization. Source
fixtures must be invented and keep canonical identity matching separate from display labels.
Unit tests establish policy; actual disposable database tests establish SQL/transaction behavior.
Real OCI, corporate SSO, managed services and cloud restore require separate qualification.
